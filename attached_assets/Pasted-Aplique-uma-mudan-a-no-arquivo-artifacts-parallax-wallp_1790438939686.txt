OBJETIVO
═══════════════════════════════════════════════

Hoje, quando a tela de Composição entra, a rolagem automática começa
quase imediatamente — o usuário nem chega a "ver" a tela antes de ela
rolar. O Preview já tem um delay de 450ms antes de começar a rolar,
que dá tempo ao olho de perceber que falta algo abaixo. Vamos replicar
esse mesmo delay na Composição.

Reorganize para que a chamada de animateScrollTo fique dentro de um
setTimeout de 450ms, guardado na nova ref. Ou seja:

  useEffect(() => {
    if (mode !== 'compose' || !composeAttentionPending.current) return;
    if (composeScrollViewportHeight.current <= 0 || composeScrollContentHeight.current <= 0) return;
    const frame = requestAnimationFrame(() => {
      const targetY = composeLayerPickerY.current;
      if (targetY === null) return;
      composeAttentionPending.current = false;
      const maxScrollY = Math.max(
        0,
        composeScrollContentHeight.current - composeScrollViewportHeight.current,
      );
      const startY = Math.min(Math.max(0, composeScrollY.current), maxScrollY);
      const scrollTargetY = Math.min(maxScrollY, Math.max(0, targetY - 24));
      composeScrollY.current = startY;
      composeStartTimeout.current = setTimeout(() => {
        composeStartTimeout.current = null;
        animateScrollTo(composeScrollRef, composeScrollY, composeScrollFrame, scrollTargetY, () => {
          middlePickerAttention.start(120);
          foregroundPickerAttention.start(820);
          previewButtonAttention.start(1520);
        });
      }, 450);
    });
    return () => {
      cancelAnimationFrame(frame);
      if (composeStartTimeout.current !== null) {
        clearTimeout(composeStartTimeout.current);
        composeStartTimeout.current = null;
      }
      if (composeScrollFrame.current !== null) cancelAnimationFrame(composeScrollFrame.current);
    };
  }, [...]);

Observações:
- O cálculo de maxScrollY, startY, scrollTargetY e composeScrollY.current
  continua FORA do setTimeout, como no Preview. Só a chamada de
  animateScrollTo é que fica adiada.
- Os três pulses (start(120), start(820), start(1520)) continuam dentro
  do callback do animateScrollTo, sem alteração.
- O dependency array permanece exatamente igual. Não adicione nem
  remova itens.
