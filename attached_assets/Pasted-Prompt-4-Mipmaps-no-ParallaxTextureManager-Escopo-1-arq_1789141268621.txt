Prompt 4 — Mipmaps no ParallaxTextureManager
Escopo: 1 arquivo — ParallaxTextureManager.java.

Duas alterações pontuais no método uploadTexture.

4.1 — Filtro MIN com mipmap trilinear
Localize no método uploadTexture:

java
    GLES20.glTexParameteri(
        GLES20.GL_TEXTURE_2D,
        GLES20.GL_TEXTURE_MIN_FILTER,
        GLES20.GL_LINEAR);
Substitua por:

java
    GLES20.glTexParameteri(
        GLES20.GL_TEXTURE_2D,
        GLES20.GL_TEXTURE_MIN_FILTER,
        GLES20.GL_LINEAR_MIPMAP_LINEAR);
Não alterar o GL_TEXTURE_MAG_FILTER, que continua GL_LINEAR. Mipmaps só afetam minificação — quando a textura é desenhada menor do que sua resolução nativa. Ampliação continua com filtro linear simples.

4.2 — Gerar mipmaps após o upload
Localize o bloco em uploadTexture:

java
    try {
      GLUtils.texImage2D(GLES20.GL_TEXTURE_2D, 0, bitmap, 0);
    } finally {
      bitmap.recycle();
    }

    int error = GLES20.glGetError();
Substitua por:

java
    try {
      GLUtils.texImage2D(GLES20.GL_TEXTURE_2D, 0, bitmap, 0);
    } finally {
      bitmap.recycle();
    }

    GLES20.glGenerateMipmap(GLES20.GL_TEXTURE_2D);

    int error = GLES20.glGetError();
Verificação após o patch
Busca em ParallaxTextureManager.java:

GL_LINEAR_MIPMAP_LINEAR → 1 ocorrência (dentro de uploadTexture).

glGenerateMipmap → 1 ocorrência (imediatamente após o bloco try/finally de texImage2D).

GL_TEXTURE_MAG_FILTER com GL_LINEAR → continua intacto.

O glGetError existente logo abaixo capturará falhas em qualquer uma das chamadas GL — incluindo glGenerateMipmap.

Nenhum outro arquivo foi alterado.

Comportamento resultante
Antes: quando a camada era desenhada em tamanho menor do que sua textura nativa (caso comum com fitScale < 1 em retrato), o sampler GL_LINEAR fazia bilinear sampling direto na textura de maior resolução, pulando texels. Resultado: aliasing — "serrilhado" ou "cintilação" visível durante movimento.

Depois: a cadeia de mipmaps é gerada automaticamente pela GPU. Durante minificação, o trilinear filtering interpola entre dois níveis de mipmap, suavizando a transição. Resultado: menos aliasing em movimento.

Custo:

Memória de textura: ~33% maior (a cadeia completa soma 1/3 do nível base).

Tempo de upload: uma chamada glGenerateMipmap a mais por textura. Custo único, no carregamento.

Tempo de renderização: praticamente inalterado — a GPU já fazia bilinear; agora faz trilinear em minificação, custo marginal.

Trade-off: para um app premium em que a qualidade visual é o critério, o ganho supera o custo de memória.

Ponto de atenção
GL_LINEAR_MIPMAP_LINEAR exige que mipmaps existam. Sem o glGenerateMipmap, a textura ficaria completamente preta sempre que fosse minificada (a GPU considera a textura "incompleta" e descarta o conteúdo). Por isso as duas alterações devem ser aplicadas juntas — nunca só a 4.1.

Se por qualquer motivo a 4.2 falhar em produção (driver exótico), o sintoma será wallpaper preto. O glGetError existente reportaria o problema, mas a ordem de aplicação garante que ambos os blocos vão juntos no mesmo patch.
