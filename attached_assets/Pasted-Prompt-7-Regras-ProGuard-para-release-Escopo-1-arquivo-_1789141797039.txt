Prompt 7 — Regras ProGuard para release
Escopo: 1 arquivo de configuração. Sem alteração de código Java.

Este é o último prompt da série.

Etapa 1 — Verificar o estado atual
Antes de qualquer alteração, abra android/app/build.gradle e confira o bloco buildTypes:

gradle
android {
    buildTypes {
        debug {
            ...
        }
        release {
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro"
        }
    }
}
Três cenários possíveis:

minifyEnabled true e shrinkResources true — R8 está ativo. O Prompt 7 é crítico — sem ele, ParallaxWallpaperService será removido e o wallpaper para de funcionar em release.

minifyEnabled false — R8 não roda. O Prompt 7 é preventivo — não faz diferença agora, mas evita problema futuro se você ativar minificação.

Bloco release ausente ou incompleto — Expo/RN geralmente cria por padrão. Se estiver incompleto, seguimos apenas com o proguard-rules.pro e não tocamos no build.gradle neste prompt.

Anote em qual cenário você está. A decisão de adicionar/alterar build.gradle depende disso.

Etapa 2 — Adicionar regras em proguard-rules.pro
Arquivo: android/app/proguard-rules.pro

Se o arquivo existe (Expo/RN cria por padrão), adicione ao final, sem remover nada do conteúdo atual:

proguard
# Parallax Wallpaper — manter entradas referenciadas apenas pelo AndroidManifest
-keep class com.parallaxwallpaper.app.ParallaxWallpaperService { *; }
-keep class com.parallaxwallpaper.app.ParallaxWallpaperModule { *; }
-keep class com.parallaxwallpaper.app.ParallaxWallpaperPackage { *; }

# Parallax Wallpaper — manter classes internas acessadas via JNI/reflexão do sistema
-keep class com.parallaxwallpaper.app.ParallaxEglThread { *; }
-keep class com.parallaxwallpaper.app.ExifOrientationHelper { *; }

# Manter métodos anotados com @ReactMethod (chamados por reflexão do RN)
-keepclassmembers class * {
    @com.facebook.react.bridge.ReactMethod <methods>;
}
Se o arquivo não existe, crie-o com exatamente esse conteúdo.

Justificativa de cada regra:

ParallaxWallpaperService — crítico. Referenciado apenas no AndroidManifest.xml. Sem -keep, R8 remove a classe e o wallpaper some em release sem nenhum aviso no build.

ParallaxWallpaperModule e ParallaxWallpaperPackage — referenciados pelo MainApplication.kt. R8 normalmente preserva, mas marcar explicitamente é defesa em profundidade.

ParallaxEglThread — classe Thread instanciada pelo controller; o sistema pode consultar o nome da thread via Thread.getName() para diagnóstico. Preservar evita obfuscation no nome, o que ajuda em relatórios de crash.

ExifOrientationHelper — utilitário estático; se R8 inlinar, nada quebra, mas manter explícito facilita stack traces legíveis em release.

-keepclassmembers com @ReactMethod — o RN chama os métodos do módulo por reflexão. Sem isso, R8 renomeia os métodos e o RN deixa de encontrá-los, gerando Unable to find method ... em runtime.

Etapa 3 — Ajustar build.gradle apenas se estiver no cenário 3
Se o bloco release no android/app/build.gradle não existir ou não apontar para proguard-rules.pro, adicione/ajuste para:

gradle
android {
    ...
    buildTypes {
        release {
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro"
        }
    }
}
Atenção: habilitar minifyEnabled pela primeira vez pode expor problemas latentes em outros módulos RN/Expo que não têm regras ProGuard. Se você não tem certeza de que o projeto já rodava release com R8 ativo, não habilite agora — deixe minifyEnabled false e o proguard-rules.pro fica pronto para quando você decidir ativar. É decisão separada, de produto/infra, não deste prompt.

Se o projeto já compila release com R8 ativo (cenário 1), nenhuma alteração no build.gradle é necessária — apenas o proguard-rules.pro.

Verificação empírica (após o próximo build release)
Após o próximo build release, teste em dispositivo físico:

Wallpaper aparece na lista de live wallpapers do Android — confirma que ParallaxWallpaperService sobreviveu ao R8.

Aplicar o wallpaper funciona — confirma que ParallaxWallpaperService foi instanciado.

Abrir a tela do app que configura a composição — se houver erro Unable to find method ..., o -keepclassmembers para @ReactMethod não pegou. Se funcionar, tudo certo.

Ativar o wallpaper e ver o parallax rodando — confirma que a cadeia toda sobreviveu.

Em Logcat de release, você deve ver apenas os AppLog.e (prompt 6), nenhum AppLog.i. Isso confirma que o gate do prompt 6 está funcionando e que o R8 não alterou o comportamento esperado.

Observação sobre debug vs release
ProGuard só roda em release. Se você só faz builds de debug durante o desenvolvimento, o Prompt 7 não tem efeito observável até o primeiro release real. Não é motivo para pular — o objetivo é justamente evitar que o problema apareça na hora errada.
