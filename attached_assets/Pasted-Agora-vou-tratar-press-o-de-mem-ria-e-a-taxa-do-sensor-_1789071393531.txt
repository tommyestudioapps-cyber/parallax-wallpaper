Agora vou tratar pressão de memória e a taxa do sensor. Isso ataca diretamente "impedir travamentos" e "não consumir bateria".

Objetivo desta alteração
Adicionar onTrimMemory(int level) à interface WallpaperRenderer para que o sistema possa pedir liberação de memória sob pressão.

Implementar em CanvasWallpaperRenderer: reciclar bitmaps e marcar reload quando a memória ficar baixa.

Implementar em ParallaxEglController: parar a thread EGL (que libera texturas) e marcar pendingReload.

Encaminhar no ParallaxWallpaperService via Service.onTrimMemory → engine → render thread → renderer.

Reduzir a taxa do sensor de 16000µs (62,5 Hz) para 33000µs (~30 Hz). Parallax não precisa de 60 Hz — 30 Hz é visualmente fluido e reduz praticamente pela metade o custo do sensor.

Como as mudanças estão acopladas, mostro os quatro arquivos.

Adicione um método à interface:

Só isso. Os dois renderers existentes passam a precisar implementar onTrimMemory.

2. CanvasWallpaperRenderer.java
Adicione o método onTrimMemory e o import de ComponentCallbacks2. Como ele é chamado a partir da renderThread (veremos no serviço), roda com segurança ao lado de drawFrame.

Adicione no topo:

java
import android.content.ComponentCallbacks2;
E, em qualquer lugar dentro da classe (sugestão: após release()):

java
@Override
public void onTrimMemory(int level) {
  if (level < ComponentCallbacks2.TRIM_MEMORY_RUNNING_LOW) return;
  recycleBitmaps();
  composition = null;
  compositionJson = null;
  compositionLayerKey = null;
  reloadCompositionRequested = true;
  Log.i(TAG, "PARALLAX_CANVAS_TRIM_MEMORY level=" + level);
}
Reaproveita os campos existentes.

Como será executado na renderThread, não conflita com drawFrame.

O próximo renderFrame() recarrega a composição do SharedPreferences normalmente.

3. ParallaxEglController.java
Adicione o import:

java
import android.content.ComponentCallbacks2;
E o método (sugestão: após invalidateComposition()):

java
@Override
public void onTrimMemory(int level) {
  if (level < ComponentCallbacks2.TRIM_MEMORY_RUNNING_LOW) return;
  ParallaxEglThread threadToStop = null;
  synchronized (stateLock) {
    pendingReload = true;
    if (eglThread != null && state != State.STOPPING) {
      state = State.STOPPING;
      threadToStop = eglThread;
    }
  }
  if (threadToStop != null) threadToStop.requestStop();
  Log.i(TAG, "PARALLAX_EGL_TRIM_MEMORY level=" + level);
}
Ao parar a thread, ParallaxGlRenderer.release() chama textureManager.releaseTextures(), liberando as texturas.

pendingReload = true garante que, ao reiniciar (via startIfPossible() chamado por onEglThreadTerminated), a próxima carga já recarregue tudo do SharedPreferences.

4. ParallaxWallpaperService.java
Três ajustes pontuais:

(a) Trocar a taxa do sensor. Onde está:

java
sensorManager.registerListener(this, rotationSensor, 16000);
troque por:

java
sensorManager.registerListener(this, rotationSensor, 33000);
(b) Adicionar override de onTrimMemory na classe ParallaxWallpaperService (fora da classe interna ParallaxEngine):

java
@Override
public void onTrimMemory(int level) {
  super.onTrimMemory(level);
  ParallaxEngine engine = activeEngine;
  if (engine != null) engine.onTrimMemory(level);
}
(c) Adicionar o método onTrimMemory dentro da classe ParallaxEngine (por exemplo, perto de onCompositionChangedExternally):

java
void onTrimMemory(final int level) {
  renderHandler.post(new Runnable() {
    @Override
    public void run() {
      if (destroyed) return;
      WallpaperRenderer currentRenderer = renderer;
      if (currentRenderer != null) currentRenderer.onTrimMemory(level);
    }
  });
}
Isso garante que a chamada chega na render thread, respeitando a mesma afinidade de thread usada por drawFrame (Canvas) e por switchRenderer/requestFrame.

O que isso resolve na prática
Travamentos por pressão de memória: quando o sistema avisa que está com pouca memória, o wallpaper libera bitmaps/texturas imediatamente. Sem isso, o Android pode matar o processo do wallpaper de forma abrupta — o que se manifesta como flicker ou reset visual.

Bateria: o sensor cai de ~62 Hz para ~30 Hz. O serviço já tinha a dead zone maior (0.12), então o número de frames disparados praticamente não muda — só o custo de ler e processar o sensor diminui.

Compatibilidade: onTrimMemory é seguro em todas as versões suportadas. A checagem level < TRIM_MEMORY_RUNNING_LOW filtra apenas os casos em que vale a pena liberar.

Verificação rápida de consistência
Canvas: onTrimMemory roda na renderThread. drawFrame também. Sem race.

OpenGL: onTrimMemory para a thread EGL e marca pendingReload. Ao terminar de parar, onEglThreadTerminated reinicia a thread (graças à condição pendingReload || threadHadEglReady que já introduzimos no passo 2). A nova thread recarrega texturas.

Serviço: activeEngine é volatile, renderHandler sempre existe depois do construtor do engine. Nenhuma race nova.

Interface: os dois renderers implementam o novo método — nada quebra compilação.
