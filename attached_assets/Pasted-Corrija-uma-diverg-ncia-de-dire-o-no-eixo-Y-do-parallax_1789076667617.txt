Corrija uma divergência de direção no eixo Y do parallax entre o renderer Canvas e o renderer OpenGL.

Arquivo: android/app/src/main/java/com/parallaxwallpaper/app/ParallaxGlRenderer.java

Problema:
No CanvasWallpaperRenderer.drawLayer, o offset de parallax em Y é somado diretamente à coordenada top do retângulo de destino:

java
float motionTop = snapshot.getY() * multiplier * coordinateScale;
float top = (canvasHeight - height) / 2f + layerY + motionTop;
Como o sistema de coordenadas do Canvas tem Y crescendo para baixo, um sensorY positivo empurra a camada para baixo.

No OpenGL, o offset é somado em clip space, onde Y positivo aponta para cima:

glsl
vec4 clipPosition = u_MVPMatrix * vec4(a_Position, 0.0, 1.0);
clipPosition.xy += u_Offset * u_DepthFactor;
gl_Position = clipPosition;
Em ParallaxGlRenderer.updateSensorState, o Y é normalizado sem inversão:

java
motionY = sensorMotionY * 2f * surfaceWidth / (compositionWidth * surfaceHeight);
Resultado: para o mesmo sensorY, o Canvas move a camada para baixo e o OpenGL move para cima. Ao alternar entre RENDERER_CANVAS e RENDERER_OPENGL, o parallax inverte a direção vertical.

Correção desejada:
Inverter o sinal de motionY em updateSensorState, alinhando o OpenGL ao Canvas.

Localize em ParallaxGlRenderer.java o método updateSensorState e substitua a linha:

java
    motionY = sensorMotionY * 2f * surfaceWidth / (compositionWidth * surfaceHeight);
por:

java
    motionY = -sensorMotionY * 2f * surfaceWidth / (compositionWidth * surfaceHeight);
Atualize também o comentário acima do bloco para refletir a inversão. Substitua o comentário atual:

java
    // Mesma normalização do Canvas: motionPixels = sensorX * multiplier * (W / compositionWidth).
    // Convertendo pixels -> NDC e deixando o u_DepthFactor multiplicar em runtime:
    //   offsetX = sensorX * 2 / compositionWidth
    //   offsetY = sensorY * 2 * surfaceWidth / (compositionWidth * surfaceHeight)
    // O Y precisa do aspect ratio porque o Canvas desloca em pixels do eixo X
    // e converte para NDC-Y usando a altura real da superfície.
por:

java
    // Mesma normalização do Canvas: motionPixels = sensorX * multiplier * (W / compositionWidth).
    // Convertendo pixels -> NDC e deixando o u_DepthFactor multiplicar em runtime:
    //   offsetX =  sensorX * 2 / compositionWidth
    //   offsetY = -sensorY * 2 * surfaceWidth / (compositionWidth * surfaceHeight)
    // O Y precisa do aspect ratio porque o Canvas desloca em pixels do eixo X
    // e converte para NDC-Y usando a altura real da superfície. O sinal é negativo
    // porque o Canvas tem Y crescendo para baixo e o clip space do OpenGL tem Y
    // crescendo para cima.
Restrições:

Não altere mais nada no arquivo. Nada em renderFrame, updateLayerMvp, updateLayerUvTransform, shader, validateAlphaPrecision, AlphaPrecisionGlState ou em qualquer outro método.

Não altere CanvasWallpaperRenderer — ele é a referência correta.

Não altere assinaturas nem adicione novos métodos.

Não altere o comportamento do eixo X.

Verificação esperada após a correção:

Com a mesma composição e o mesmo movimento do sensor, alternar entre RENDERER_CANVAS e RENDERER_OPENGL deve produzir deslocamento vertical na mesma direção.

Inclinar o aparelho para frente deve mover as camadas para o mesmo lado em ambos os renderizadores, sem "inverter" ao trocar de modo.

Nenhum log novo de falha deve aparecer no Logcat (PARALLAX_GL_SHADER_COMPILE_FAILED, PARALLAX_RENDERER_FALLBACK, PARALLAX_GL_ALPHA_PRECISION_FAILED ausentes como consequência da mudança).

O log PARALLAX_GL_ALPHA_PRECISION_VALIDATION PASSED continua aparecendo normalmente.
