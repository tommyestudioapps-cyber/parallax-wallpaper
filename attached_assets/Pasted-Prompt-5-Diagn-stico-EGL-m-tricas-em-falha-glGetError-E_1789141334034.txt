Prompt 5 — Diagnóstico EGL + métricas em falha + glGetError
Escopo: 1 arquivo — ParallaxEglThread.java.

Três alterações correlatas, todas dentro desse arquivo.

5.1 — Log de extensões EGL suportadas
Localize em initializeEgl, o final do método:

java
    Log.i(TAG, "PARALLAX_EGL_READY");
    return true;
  }
Substitua por:

java
    Log.i(TAG, "PARALLAX_EGL_READY");
    String extensions = EGL14.eglQueryString(currentDisplay, EGL14.EGL_EXTENSIONS);
    Log.i(TAG, "PARALLAX_EGL_EXTENSIONS " + (extensions == null ? "(none)" : extensions));
    return true;
  }
Motivo: em diagnóstico de campo, saber quais extensões EGL o driver expõe é pré-requisito para entender falhas específicas de aparelho. Sem esse log, um bug reportado por um usuário com GPU exótica é impossível de investigar sem pedir build customizado.

5.2 — Log explícito quando nenhum frame foi desenhado
Localize em emitGlMetricsIfNeeded:

java
  private void emitGlMetricsIfNeeded(boolean force) {
    if (metricsWindowFrames == 0L) return;
Substitua por:

java
  private void emitGlMetricsIfNeeded(boolean force) {
    if (metricsWindowFrames == 0L) {
      if (force) {
        Log.i(TAG, "PARALLAX_GPU_METRICS_EMPTY reason=no_frames_drawn"
            + " totalGlFrames=" + totalGlFrames
            + " vsyncMisses=" + vsyncMisses
            + " swapFailures=" + metricsWindowSwapFailures);
      }
      return;
    }
Motivo: quando o thread EGL morre antes de desenhar qualquer frame (falha em initializeEgl ou initializeGlRenderer), o finally chama emitGlMetricsIfNeeded(true), que antes retornava em silêncio. Agora emite um marcador distinto. Isso distingue "nunca rodou" de "rodou e parou" nos logs de diagnóstico.

5.3 — glGetError após renderFrame
Localize o loop principal em run():

java
        ParallaxSensorState snapshot = sensorState;
        glRenderer.updateSensorState(snapshot.getX(), snapshot.getY());
        long frameStartNs = System.nanoTime();
        glRenderer.renderFrame();
        long swapStartNs = System.nanoTime();
Substitua por:

java
        ParallaxSensorState snapshot = sensorState;
        glRenderer.updateSensorState(snapshot.getX(), snapshot.getY());
        long frameStartNs = System.nanoTime();
        glRenderer.renderFrame();
        int glError = GLES20.glGetError();
        if (glError != GLES20.GL_NO_ERROR) {
          Log.e(TAG, "PARALLAX_GL_RENDER_ERROR error=0x"
              + Integer.toHexString(glError)
              + " frame=" + totalGlFrames);
        }
        long swapStartNs = System.nanoTime();
Motivo: o driver OpenGL ES pode registrar erros no pipeline sem quebrar a chamada de swap. Sem glGetError, esses erros ficam invisíveis. Agora cada erro é logado com o número do frame, ajudando a correlacionar com o estado do renderer no momento. totalGlFrames é incrementado em recordGlFrame — como essa chamada acontece depois, o frame= no log refere-se ao frame anterior, o que é aceitável para diagnóstico.

Import GLES20 já existe no arquivo. Nada a adicionar.

Decisão de design: o glGetError não dispara reportFailure. A maioria dos erros GL é transitória e o retry do controller (Prompt anterior) já cobre o caso de falha real. Matar o thread a cada erro intermitente seria pior que deixar rodar.

Busca em ParallaxEglThread.java:

PARALLAX_EGL_EXTENSIONS → 1 ocorrência (dentro de initializeEgl).

PARALLAX_GPU_METRICS_EMPTY → 1 ocorrência (dentro de emitGlMetricsIfNeeded).

PARALLAX_GL_RENDER_ERROR → 1 ocorrência (dentro do loop de run()).

eglQueryString → 1 ocorrência.

glGetError → agora aparece 2 vezes: uma no initializeEgl original (se houver) e uma nova no loop. Vale conferir que não colide com nenhuma existente.

Nenhum outro arquivo foi alterado.

Comportamento resultante
Logcat em condições normais:

Novo: PARALLAX_EGL_EXTENSIONS EGL_KHR_... uma vez no início.

Nenhum PARALLAX_GL_RENDER_ERROR em uso normal.

Nenhum PARALLAX_GPU_METRICS_EMPTY — esse só aparece quando o thread morre sem desenhar.

Logcat em falha de inicialização EGL:

PARALLAX_EGL_GET_DISPLAY_FAILED ou equivalente.

PARALLAX_RENDERER_FALLBACK reason=egl_initialization retryIn=3000ms attempt=1.

PARALLAX_GPU_METRICS_EMPTY reason=no_frames_drawn totalGlFrames=0 ... — novo marcador que confirma "nada foi desenhado".

Logcat em erro silencioso de driver:

PARALLAX_GL_RENDER_ERROR error=0x502 frame=1234 — novo marcador com o código GL (0x502 = GL_INVALID_OPERATION, por exemplo).

Custo
eglQueryString: uma chamada por inicialização do thread EGL. Custo desprezível.

glGetError por frame: uma chamada de API GL por frame. Custo desprezível em GLES 2 (é uma leitura de flag interna). Em GPUs muito antigas, podia ser custoso em drivers desktop; em mobile, é seguro.

Log de PARALLAX_GPU_METRICS_EMPTY: condicional, só quando metricsWindowFrames == 0 e force == true.

Ponto de atenção
O PARALLAX_GL_RENDER_ERROR é chamado dentro do loop quente. Se um driver começar a emitir erros intermitentes em sequência, isso poderia poluir o Logcat. Se isso acontecer em produção, o gate de logs do Prompt 6 vai silenciar em release — mas idealmente esse log específico deve permanecer mesmo em release (é diagnóstico de falha real, não de fluxo normal). Recomendação: tratar esse log como o Log.e, que o AppLog do Prompt 6 mantém sempre ativo.

Se preferir já antecipar essa decisão, substitua Log.e(TAG, ...) por algo que sobreviva ao gate do Prompt 6 — mas o Prompt 6 vai tratar isso automaticamente na migração.
