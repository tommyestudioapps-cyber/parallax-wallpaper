PROMPT PARA O REPLIT — Corrigir sourceWidth/sourceHeight pré-EXIF
Objetivo: garantir que as dimensões de origem das camadas reflitam a geometria visual do bitmap (pós-EXIF), não a física do arquivo (pré-EXIF).

Contexto: Em ParallaxTextureManager.loadLayerBitmap e CanvasWallpaperRenderer.loadLayerBitmap, os valores boundsOptions.outWidth/outHeight são lidos antes da aplicação de EXIF e usados como sourceWidth/sourceHeight. Depois de ExifOrientationHelper.applyOrientation, o bitmap tem dimensões invertidas (em EXIF=6/8), então esses valores ficam inconsistentes com a geometria real do bitmap. O ramo sem crop (hasSourceCrop == false) usa esses valores para dimensionar o destino, e a textura resultante seria esticada.

Correção: usar sempre as dimensões do bitmap pós-EXIF como sourceWidth/sourceHeight.

Alteração 1 — ParallaxTextureManager.java
No método loadLayerBitmap, localize o bloco:

java
      if (bitmap == null) {
        Log.w(TAG, "PARALLAX_GL_BITMAP_LOAD_FAILED index=" + index + " reason=decode_null");
      } else {
        bitmap = ExifOrientationHelper.applyOrientation(context, bitmap, uriString, index);
        bitmap.prepareToDraw();
        LayerData data = mLayerData[index];
        data.sourceWidth = sourceWidth > 0 ? sourceWidth : bitmap.getWidth();
        data.sourceHeight = sourceHeight > 0 ? sourceHeight : bitmap.getHeight();
        if (data.imageWidth <= 0) data.imageWidth = data.sourceWidth;
        if (data.imageHeight <= 0) data.imageHeight = data.sourceHeight;
Substituir por:

java
      if (bitmap == null) {
        Log.w(TAG, "PARALLAX_GL_BITMAP_LOAD_FAILED index=" + index + " reason=decode_null");
      } else {
        bitmap = ExifOrientationHelper.applyOrientation(context, bitmap, uriString, index);
        bitmap.prepareToDraw();
        LayerData data = mLayerData[index];
        data.sourceWidth = bitmap.getWidth();
        data.sourceHeight = bitmap.getHeight();
        if (data.imageWidth <= 0) data.imageWidth = data.sourceWidth;
        if (data.imageHeight <= 0) data.imageHeight = data.sourceHeight;
Observação: as variáveis locais sourceWidth/sourceHeight (lidas de boundsOptions) continuam existindo — ainda são usadas por calculateInSampleSize, que precisa das dimensões físicas pré-EXIF para decidir o sampleSize. Não remover essas variáveis, apenas parar de usá-las para preencher LayerData.sourceWidth/Height.

Restrições
Não alterar mais nada em nenhum dos dois arquivos.

Não alterar calculateInSampleSize — o inSampleSize deve continuar sendo calculado sobre a resolução física (pré-EXIF) do arquivo, porque essa é a resolução real de amostragem do decoder.

Não alterar ParallaxGlRenderer, ParallaxEglController, ParallaxEglThread, ParallaxWallpaperService, ExifOrientationHelper nem o shader.

Não criar novos imports.

Não alterar nomes de variáveis locais nem assinaturas de método.

Justificativa
O inSampleSize é uma decisão sobre quantos pixels decodificar, e a resposta correta depende da resolução física do arquivo — daí ele continuar sendo calculado sobre boundsOptions.outWidth/outHeight. Isso não muda.

Já sourceWidth/sourceHeight são uma decisão sobre como a imagem se apresenta visualmente ao usuário, e a resposta correta depende da geometria pós-rotação. Depois do applyOrientation, o bitmap é a única fonte confiável dessas dimensões. Usar boundsOptions aqui produz valores invertidos em fotos com EXIF=6/8 e distorce silenciosamente o ramo sem crop.

Verificação esperada após o patch
Compilação sem erros.

Logcat, ao carregar uma foto com EXIF=6:

PARALLAX_EXIF_APPLIED index=N orientation=6 width=W height=H

PARALLAX_GL_BITMAP_READY index=N width=W height=H sampleSize=S

Os W/H devem coincidir em ambas as linhas.

Com uma composição sem sourceCrop em pelo menos uma camada, a foto não deve apresentar alongamento em nenhum dos dois renderizadores (GL e Canvas).

Com uma composição com sourceCrop, o comportamento já validado nos testes anteriores deve permanecer inalterado.
